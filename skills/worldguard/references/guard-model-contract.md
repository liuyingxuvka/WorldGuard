# Native Guard responsibilities and author regression

WorldGuard runs the selected native Guard and semantic executor directly against the current model. Ordinary tasks do not declare checker calibration fixtures, selected checker failures, frozen purpose bindings, or construction-order receipts. Keep the world model purpose, assumptions, scope and evidence explicit.

The seven native Guards own their domain boundaries. `python -m worldguard.guard_model_contract` is an author-side finite regression: one known-good per Guard and one known-bad for every current Guard-owned failure code (81 in 0.7.12). It executes each case once. Provider availability and mesh registration have separate owners. This catalog is not a task-understanding score or a precondition for ordinary model execution.

Blueprint target BehaviorCase inputs, expected output, post-state and effects are real target modeling/test evidence. They retain their native oracle, exact current-input binding and external-test/evidence checks; they are separate from author calibration.
