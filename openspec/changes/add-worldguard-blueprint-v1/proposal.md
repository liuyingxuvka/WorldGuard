## Why

WorldGuard now has a converged qualification path and a native `WorldBlueprint` product slice, but its FlowGuard self-model still does not describe the complete repository well enough to act as the software's own reproducible DNA. This change keeps `WorldBlueprint` as one product-capability subtree while adding one whole-repository self-DNA root, seven explicit Guard subtrees, complete non-language-specific ownership and binding coverage, affected-only maintenance, independent export, and proof-gated architecture reduction.

## What Changes

- Replace the ordinary-versus-mesh duplicate qualification paths with one current owner that derives required Guards, rejects unmapped semantics, executes each structural and semantic owner once, preserves provider evidence, and produces one typed qualification report.
- Add a hierarchical `WorldBlueprint` with one root, single parent ownership, typed ports, stable world-element identity, dependency edges, explicit abstraction depth, and complete child-output/parent-input accounting.
- Bind world elements to target material, evidence, tests, and native Guard receipts, or retain a typed gap explaining the missing binding.
- Separate candidate consistency from an externally licensed object-DNA claim. A portable, independently signed object census fixes the complete target/node/element/Guard/support-role/derivation denominator and the exact request, material, and semantic-authority input identities; the caller must trust that exact authority or producer fingerprint before WorldGuard may report object-DNA qualification.
- Add exact affected-only impact analysis and reverse trace from a world output/claim to its elements, inputs, evidence, tests, and native results.
- Reject unknown relation kinds instead of silently converting them to `depends_on`; remove any duplicate semantic execution owner exposed by qualification convergence.
- Add one `blueprint` CLI group with `check`, `impact`, and `trace` operations and a three-level non-code workflow fixture.
- Add a later-bound FlowGuard projection with stable provider identity and fingerprints; ordinary WorldGuard checks remain independent of FlowGuard, and no local generic blueprint fallback is added.
- Add one WorldGuard repository self-DNA root above the seven Event/Agent/Space/Resource/Causal/Conflict/Norm Guard subtrees and the shared runtime, mesh, `WorldBlueprint`, prompt, validation, projection, installation, and release subtrees; the product `WorldBlueprint` is not the self-DNA root.
- Derive the complete repository denominator independently of existing models or caller file lists, give every code and non-code surface one terminal disposition and one primary owner, and bind model behavior as `Input × State -> Set(Output × State)` to intent, topology, implementation, tests, resources, evidence, and oracles.
- Qualify static self-DNA through the seven provider-neutral FlowGuard layers—evidence qualification, implementation inventory, traceability, independent semantics, model-code-test binding, resource-oracle binding, and static blueprint readiness—while maintaining deterministic affected and reverse indexes for ordinary affected-only work.
- Produce a canonical content-addressed self-DNA export outside the governed repository as an independent materialization of the same static blueprint so the export cannot enter its own inventory or fingerprint; verify isolated import without treating export, test execution, external-resource availability, installation, Git/tag/GitHub Release, or release assets as deeper static understanding.
- Permit architecture contraction only after the exact current self-DNA and observable-contract evidence make a candidate proof-ready; retain uncertain surfaces and distinct evidence owners rather than deleting them for size or similarity.
- Update the single WorldGuard skill, conditional references, prompt budget, SkillGuard contract, runtime projection, tests, and release artifacts.
- Keep the seven-Guard matrix as an oracle-carrying capability fixture rather than presenting its detached zero-interface cases as one integrated seven-Guard target. Preserve the genuinely different policy target on the same public route.

## Capabilities

### New Capabilities

- `worldguard-world-blueprint`: Native hierarchical world/workflow elements, interfaces, artifact/test/evidence bindings, qualification, and understanding-depth boundary.
- `worldguard-blueprint-impact-trace`: Affected-only impact and reverse trace with exact paths and visible gaps.
- `worldguard-blueprint-flowguard-projection`: Optional current FlowGuard projection plus the generic whole-repository self-DNA boundary, preserving WorldGuard semantic ownership, complete denominator identity, the seven provider-neutral static-readiness layers, affected/reverse indexes, and a separately qualified canonical external materialization while failing visibly when authority is unavailable or stale.
- `worldguard-consumer-installation`: One read-only installation-currentness path delegated to the exact installed SkillGuard consumer-distribution authority, with projection-only freshness, one external `worldguard` skill, and a release-asset boundary that keeps canonical self-DNA export separate from installation authority.

### Modified Capabilities

- `worldguard-runtime`: Ordinary and mesh execution must consume one qualification report and execute each native owner once.
- `claim-derived-semantic-coverage`: Required Guards come only from structured claim semantics and cannot be narrowed by caller declarations.
- `semantic-rollout-status`: Structural, semantic, provider, rollout, and final qualification states remain distinct; structural-only evidence cannot license semantic completion.
- `worldguard-model-mesh`: Mesh nodes consume current qualification reports and strict typed relations without a second semantic loop or relation fallback.
- `world-model-deepening`: Deepening must expose parent/child ports, element ownership, bindings, affected scope, reverse trace, and the first unresolved gap.
- `worldguard-route-loading`: Blueprint references load only for explicit blueprint/depth/impact/trace needs and the affected internal Guard set.
- `worldguard-template-pack-builder`: Zero matching templates block; the shared base is a construction fragment, never a selected fallback.
- `worldguard-entry-topology`: Public facades, portable launchers, CLI terminal policy, and validation entry surfaces must delegate to one current owner without becoming alternate success or evidence paths.

## Impact

This affects WorldGuard contracts, kernel, mesh, reports, CLI, qualification, the native domain blueprint, the independent repository inventory and self-blueprint, skill prompts/references, bundled runtime projection, SkillGuard checks, OpenSpec authority, focused and full tests, canonical external export, installation-currentness auditing, release assets, and the patch release after the external FlowGuard toolchain stabilizes. The seven internal Guards retain their distinct structural and semantic ownership, remain internal rather than installed child skills, and become explicit subtrees of the one WorldGuard software-DNA root.
